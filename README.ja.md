# Commando Workshop

見下ろし型・縦スクロールの小さなシューティングゲームです。AIコーディングエージェント（Claude Code、Codex、OpenCode）を使ってゲームの土台づくりを学ぶ、ハンズオンワークショップの出発点として使います。

![](docs/screenshot.png)

## 実行

```sh
pnpm install
pnpm dev
```

操作: **WASD** 移動 · **マウス** 照準 · **クリック** 射撃 · **Space / 右クリック** 手榴弾 · **R** リスタート。

捕虜を救出し、最上部までたどり着いてください。トーチカと戦車には銃弾が効きません。手榴弾を使うか、近くの赤いドラム缶を利用してください。

## 演習2: データ + エディタ

レベルと敵は TOML ファイルで `data/` にあり、ゲームの横のページにエディタがあります。

- **マップを編集する:** *Terrain*（地形）または *Units*（ユニット）を選び、パレットから選んで、マップ上をクリックまたはドラッグします。Shift+ドラッグで矩形を塗りつぶし、
  右クリックでカーソル下の内容を拾い、⌘Z / ⇧⌘Z で元に戻す／やり直します。行番号をクリックすると、*Play from row*（その行から開始）の開始位置を選べます。
  マップ上の青い枠はゲームが表示している範囲、黄色い点はプレイヤーです。
- **敵を編集する:** *Enemies* タブに、敵の種類ごとのフォームがあります。能力値、移動の仕組み1つ、攻撃の仕組み1つです。
  *Clone as new type* で、コードに触れずに新しい種類を作れます（例えばもっと速いスナイパー）。
- **保存**（⌘S）すると `data/levels/<name>.toml` と `data/enemies.toml` に書き込まれ、ゲームが読み込み直します。ほかの手段（テキストエディタやコーディングエージェント）で
  ファイルが変更された場合も同じように再読み込みされます。ファイルが不正な場合は、ゲームは最後に有効だったバージョンで動き続け、パネルに問題点が表示されます。
  コマンドラインからは `pnpm check:data` でファイルを検証できます。
- **レベル:** ドロップダウンでレベルを切り替えます（URL の `?level=name`）。*New…* で空のレベルを作ります。
- **開発用のみ:** エディタとファイル API は `pnpm dev` の一部です。`pnpm build` で作ったゲームはレベルを読み込めません。

ファイル形式は、各データファイルの冒頭と `AGENTS.md` に記載されています。

## このブランチ: 演習3、エディタの中のエージェント

エディタの Map タブの上部にある *Ask an agent* セクションで、一文の指示からマップを編集できます。

1. **触ってよい範囲を選ぶ:** 行番号の上をドラッグして行を選択します（マップ全体のままでも構いません）。地形・ユニット・両方のどれを変更してよいかもチェックで指定します。
   *Game view* を押すと、現在画面に表示されている行が選択されます。
2. **依頼する**（⌘↵）: 開発サーバーがプロンプト（ルール、凡例、各敵の動き、マップ全体、選択範囲、直近の依頼）を組み立て、
   ドロップダウンで選んだコーディングエージェントの CLI（`claude -p`、`codex exec`、`opencode run`）をヘッドレスで実行します。処理中もゲームを続けて遊べます。
   待っている間、パネルには何が起きているかが表示されます。各ステップ、送ったプロンプトそのもの、Claude がどれだけ考えたか、そして1行ずつ書かれていく回答です
   （Codex はステップを報告し、回答は最後にまとめて送ります）。
3. **確認する:** 回答は検証されます（有効なコード、歩行可能な経路、ユニットが歩行可能なセルの上にあること、戦車が占めるセルがすべて道路上にあること、スポーン地点の近くに何もないこと、など）。
   検証に失敗した場合は問題点をエージェントに返して再試行させます（最大3回）。検証に通った回答は、変更されたセルを枠で囲んで**マップ上にプレビュー**されます。
   *Hold to see original* を押し続けると変更前が見えます。**Accept**（承認）すると通常の Undo 可能な編集として適用され、その後はいつも通り Save します。**Reject**（却下）すると破棄されます。
4. **エージェントからのメッセージ:** エージェントは `AGENT_MESSAGE:` の行で意見を返せます。既存の地形・ユニット・挙動では実現できない依頼
   （「ヘリコプターのボスを追加して」）、曖昧な依頼、頼まれた以上の変更などです。提案がなければメッセージだけが返り、提案があればその横に表示されます。
   メッセージはすべて `data/agent-messages.md` に追記されます。コーディングセッションにそのまま渡せます。

ここでのエージェントはステートレスな関数です。レベル、履歴（`data/ask_log.jsonl`）、検証を持つのはページ側です。CLI は空の一時ディレクトリで、
ツールなし（Claude）または読み取り専用サンドボックス（Codex）で実行されるため、テキストで答えることしかできません。

12 KB のプロンプトでの、ある1台のマシンでの典型的なレイテンシ: Claude Code のデフォルトモデルで約40秒、`sonnet` で約19秒、Codex で約44秒。
CLI の選択の横の欄にモデル名を入れると、品質と速度のバランスを調整できます。使う前に、コマンドラインから CLI を試してみてください:

```sh
pnpm try:agent claude "add a sniper nest on the right with cover" 30 56 sonnet
pnpm test:ask      # スクリプト化した偽のエージェントでループを検証。ネットワーク不要
```

## 演習

資料は `workshop/` にあります（まず `workshop/README.md` から。日本語版は `workshop/ja/`）。

1. **ハードコード**（`master`）: レベルは `src/level.ts` 内のテキストグリッドで、挙動はコードで書かれています。機能やエフェクトを追加します。
2. **データ + エディタ**（完成版は `exercise-2` ブランチ）: レベルと敵の定義を TOML ファイルに移し、レベルエディタとホットリロードを用意します。
3. **エディタの中のエージェント**（このブランチ、完成版）: エディタがヘッドレスのコーディングエージェントを呼び出し、依頼に応じてレベルを編集させます。
