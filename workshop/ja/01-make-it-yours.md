# 01 · 自分のゲームにする（45分）

**ゴール:** エージェントを使ってゲームを変更し、編集・リビルド・リロードのサイクルにかかるコストを体感し、**2つのエージェントを並行して**互いに干渉させずに動かします。

2つのパートを同時に進めます。先にパートBを始めてください。パートAに取り組んでいる間、パートBは動き続けます。

## パートA · 機能とエフェクト（メインのチェックアウトで）

メニューから1つか2つ選んでください（自分で考えてもかまいません）。手持ちのもので工夫するひねりが欲しければ、[制約カード](constraints.md)を引いてください。

| 分野 | アイデア |
|---|---|
| 武器 | 火炎放射器 · 拡散するショットガン · オーバーヒートするマシンガン · 爆風のあるロケット · 跳ねるグレネード |
| 敵 | 突撃してくる自爆兵 · 仲間を蘇生する衛生兵 · 着弾地点の円が見える迫撃砲 · 体当たりしてくるジープ · フェーズのあるボス |
| ワールド | 破壊できる壁 · 地雷 · 移動が遅くなる泥 · 崩れる橋 · サーチライト |
| プレイヤー | ダッシュ/ローリング · シールドのピックアップ · 一撃死の代わりの体力バー · 弾薬のピックアップ |
| フィードバック | ダメージ数値 · ヒットストップ · 連続撃破のバナー · ミニマップ · 画面揺れの調整 |
| 見た目 | 懐中電灯の光の円錐がある夜のレベル · 雨 · マズルフラッシュの光 · 爆発の陽炎 |

結果を依頼し、エージェントに `pnpm typecheck` を実行させ、さらに**ゲームを実際に見る**ようにさせてください（チートシート参照: エージェントはブラウザを操作でき、開発ビルドでは `window.game` が公開されています）。
**目で見える、または計測できる**機能を選んでください（時間を計れるダッシュ、スクリーンショットを撮れるバナーなど）。操作を追加した場合は、`src/scenes/HudScene.ts` にあるスタートバナーの操作説明も更新してください。

## パートB · オーディオ、別のワークツリーで

このゲームには音がありません。**パートAに取り組んでいる間に**、エージェントにサウンドを追加させます:

```sh
git worktree add ../commando-audio -b audio
cd ../commando-audio && pnpm install      # or: claude -w audio
pnpm dev --port 5174                      # a second copy, on its own port
```

オーディオ担当エージェントへの指示（適宜変えてください）:

> Web Audio API を使って、このゲームにサウンドを追加してください。**オーディオファイルは使いません**: 合成音で射撃、爆発、グレネードの投擲とピックアップのジングル、
> 敵への命中、捕虜（POW）の救出、ゲームオーバーを作ってください。すべてを新しい `src/audio.ts` にまとめ、ゲームコードからは**1行の呼び出し**で使ってください
> （`audio.play("shot")`）。こうすれば既存ファイルへの差分はごく小さく済みます。ブラウザは最初のクリックかキー入力まで音声をブロックするので、その対処もしてください。

動いたら: オーディオのワークツリーでコミットし（エージェントができない場合は自分で行ってください。Codex のサンドボックスはコミットをブロックします）、次にメインのチェックアウトで `git merge audio` を実行します。
**マージのために10分残しておいてください。** 両方のパートが同じ行に触れた箇所で、1つか2つのコンフリクトが起きるはずです（私たちのテストでは import の1行でした）。
手で解決するか、エージェントに頼んでください。エージェントでは24秒かかりました。

> **なぜ1ファイルの設計にするのか？** 2つのエージェントが同じファイルを並行して編集するのは、コストの高いケースです。パートBが触れる範囲が小さいほど、マージは安く済みます。

## 完了条件

- [ ] パートA: 少なくとも1つの機能がゲーム内で目に見える（または計測できる）
- [ ] パートB: ゲームから音が出て、`audio` ブランチにコミットされている
- [ ] （どちらかのエージェントではなく）あなた自身が `audio` をメインのチェックアウトにマージし、`pnpm typecheck` が通る
