# エージェント チートシート

## 2つのエージェントを同時に: ワークツリー

ワークツリーとは、同じリポジトリを別ブランチで2つ目にチェックアウトしたものです。これにより、2つのエージェントが互いのファイルに触れずに作業できます。

```sh
git worktree add ../commando-audio -b audio     # any tool
claude -w audio                                  # Claude Code can create one for you
codex --worktree                                 # so can Codex
cd ../commando-audio && pnpm install && pnpm dev --port 5174      # its own dev server, its own port
```

メインのチェックアウトに戻ってマージ: `git merge audio`。一覧と削除: `git worktree list`、`git worktree remove ../commando-audio`。
無視されているファイルは引き継がれません（`node_modules` も `.env` もありません）。各ワークツリーで `pnpm install` を実行してください。

## Codex のサンドボックス

Codex はコマンドをサンドボックス内で実行し、デフォルトでは `.git` 内に書き込めません。ファイルは編集できますが、`git commit` は失敗します。コミットは自分で行ってください
（または許可してください）。サンドボックス内ではファイル監視が変更を取りこぼすこともあります。回避策は Vite の `server.watch.usePolling` です。

## マージコンフリクト

2つのエージェントが同じ行を編集するとコンフリクトします。手で直すか、エージェントに頼みます: *「コンフリクトのあるマージの途中です。両方の意図を残して解決し、そのあと `pnpm typecheck` を実行して。」* 結果は実際に遊んで確認してください。

## エージェントに見えるようにする

- 開発ビルドではゲームが `window.game` として公開されているので、ブラウザツールを持つエージェントは状態を調べたり操作したりできます。
- ブラウザツールを持たないエージェントでも、スクリプトでブラウザを動かせます。すでに入っている Chrome で Playwright を使えば、会場の Wi-Fi で大きなブラウザをダウンロードせずに済みます:
  `chromium.launch({ channel: "chrome" })`。「遊んで」確かめるのではなく、`window.game` を通じて状態を確認するよう頼んでください。
- スクリーンショットを渡して（貼り付けるかパスを指定）、何がおかしいかを伝えます。「爆発がのっぺりして見える」は画像があるほうが伝わります。
- ブラウザはバックグラウンドのタブを抑制します。決定的なテストのために、エージェントは `game.loop.sleep()` を呼び、`game.step(time, delta)` でゲームを1ステップずつ進められます。

## 利用枠を使い切らないために

- エージェントはペアあたり2つで十分です。10セッションを並行させるとレート制限にかかり、全員が遅くなります。
- 小さく明確な作業には小さく速いモデルを使い、大きなモデルは設計上の判断やデバッグに取っておきます。
- 大きな変更の前には計画を求め、`pnpm typecheck` を自分で実行するよう伝えます。
- こまめにコミットします。動いている状態のコミットが最良の取り消し手段です。

## いつでも役立つ良い習慣

- セッションは *「AGENTS.md を読んで」* から始めます。同じことでエージェントを2回訂正したら、そのファイルに追記します。（Codex と OpenCode は `AGENTS.md` を読み、Claude Code は `CLAUDE.md` を読みます。ここでは後者は同じファイルへのリンクです。）
- 自分の作業を自分でテストさせ、そのあと3行で要約させます。
- ループにはまったら止めて、ゴールを1文で言い直し、失敗している出力を渡します。
