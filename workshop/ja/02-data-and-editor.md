# 02 · データとエディタ（45分）

**ゴール:** レベルをコードではなくします。**ゲームの実行中に**編集できるファイルにし、さらに小さなエディタで編集できるようにします。
これは「ゲーム」を「内側から形を変えられるゲーム」に変えるステップであり、後でエージェントがそれを行えるようにするステップでもあります。

## 取り決め（これをエージェントに渡すか、変更してからそれを伝えてください）

1つのレベル = `data/levels/` 内の1つの TOML ファイル。同じサイズの2つのグリッド、**16列 × N行**:

```toml
[level]
name = "River Crossing"
width = 16
height = 80

[legend.terrain]
".." = "grass"
"rd" = "road"
"##" = "wall"
"~~" = "water"
# ... one entry per terrain code

[legend.units]
"s1" = "rifleman"
"t1" = "tank, 2x2"
"h1" = "POW"
# ... one entry per unit code

[map]
terrain = '''
000 .. .. .. .. .. .. .. rd rd .. .. .. .. .. tr ..
001 .. tr .. .. .. .. .. rd rd .. .. .. .. .. .. ..
'''
units = '''
000 .. .. .. .. .. .. .. .. .. .. .. .. .. .. .. ..
001 .. .. .. .. .. .. .. .. .. .. s1 .. .. .. .. ..
'''
```

人間**と**エージェントの両方にとって扱いやすくするためのルール: すべてのセルはちょうど2文字 · セルは1つのスペースで区切る ·
すべての行は3桁の行番号で始まる（そのため「row 042」のように行を指し示せる） · 行 `000` が一番上（出口） ·
2x2のユニット（戦車）は左上のセルに書き、残りの3つのセルは `..` のままにする。
凡例はコードの意味を人とエージェントのために記録するものです。コードが実際に*何をするか*は、引き続きゲームのコードの中にあります。
既存のレベルは、ほぼこのままの形で `src/level.ts` にあります。

## プロンプトの前に決めること

私たちのテストでは、エージェント単独でこのゴールに10〜15分で到達しました。大事なのはあなたたちの時間です: **これらの判断は自分たちで行い**、エージェントに伝え、結果を説明できるようにしてください。

1. ファイルが変更されたとき、実行中のゲームはどうなりますか？ 一番下からやり直しますか、それともプレイヤーをその場に留めますか？
2. エディタに未保存のペイントがある状態で、ディスク上のファイルが変更されました。どちらの編集を優先しますか？
3. 検証はどこに置きますか？（ゲームと保存用エンドポイントで共有する関数を1つ用意すると、多くの手間が省けます。）
4. 壊れたファイルはどのように表示され、何が動き続けますか？

動いたら、**「ファイルの保存からゲームの再起動までのデータの流れを、5行で説明してください」**と聞いてください。それを図にしてください。

## ステップ（まずはゴールまで）

1. **ファイルにレベルを置く。** グリッドを `src/level.ts` から `data/levels/<name>.toml` に移し、それを読み込みます。TOML ライブラリ（`smol-toml`）が役立ちます。
2. **ホットリロード。** テキストエディタでファイルを編集して保存すると、変更を反映してゲームが再起動するようにします。誰がファイルを監視するかを考えてください: ファイルが変わったことは開発サーバーが知っています。
   ヒント: Vite は自分が import するものしか監視しないので、フォルダを追加し（`server.watcher.add("data/levels")`）、独自のイベントを送ってください（`server.ws.send(...)`）。
   TOML をモジュールとして import する方法でも動きますが、ゲームを再起動する代わりにページ全体がリロードされます。
3. **ペインター。** ゲームの横にパネルを置きます: パレット、ペイントできるグリッド、Save ボタン。ブラウザはファイルを書き込めないので、Save には開発サーバー上の小さなエンドポイントが必要です。
4. **厳密にする。** 壊れたファイル（セル数の誤り、未知のコード）は明確なエラーを出し、**クラッシュしたり最後の正常なレベルを失ったりしてはいけません**。

## 完了条件

- [ ] テキストエディタでファイルを変更すると、実行中のゲームがそれを反映してリロードされる
- [ ] 自分のエディタでタイルをペイントして Save を押すと、ゲームがそれを反映してリロードされる
- [ ] わざと壊したファイルで読みやすいエラーが表示され、ゲームは動き続ける

## 発展課題（興味のあるものを選んでください）

データとしての敵（種類の表: スプライト、HP、速度、移動パターン1つと攻撃1つ） · アンドゥ/リドゥ · 「この行からプレイ」 · カメラとプレイヤーの位置をリアルタイムで示すオーバーレイ ·
複数のレベルとレベル選択 · ドラッグで範囲選択できる行番号（演習3で欲しくなります）。

## または: 完成版を使う

完成版に切り替えて（`git worktree add ../commando-exercise-2 exercise-2`、README を参照）、次のことをしてください:

- ストーリーのある2分間のレベルをデザインする: 静かな始まり、待ち伏せ、橋、ボス。
- **Enemies** を開き、スナイパーを複製して、速さを2倍、射程を半分にする。レベルはまだ成り立ちますか？
- **プレイ中に**テキストエディタでレベルファイルを編集する。次にわざと壊して、エラーを読む。
- 編集後に `pnpm check:data` を実行する（完成版に用意されています）。
